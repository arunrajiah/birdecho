# F-Droid Submission Notes

This document captures gotchas discovered during the F-Droid metadata research. Read before submitting.

---

## ✅ Fast path: submit to IzzyOnDroid first

**Do this before tackling fdroiddata.** [IzzyOnDroid](https://apt.izzysoft.de/fdroid/) takes
pre-built APKs directly from GitHub Releases — no source build required, no android/ directory
needed, no Gradle complexity. It is included in many F-Droid clients as an extra repository and
hosts thousands of apps.

**Steps:**
1. Open https://gitlab.com/IzzyOnDroid/repo/-/issues
2. Create a new issue titled `Request: BirdEcho`
3. Provide:
   - GitHub Releases URL: `https://github.com/arunrajiah/birdecho/releases`
   - Package name: `dev.arunrajiah.birdecho`
   - License: MIT
   - Short description
4. The bot scans the APK and a human reviewer approves within a few days.

Once on IzzyOnDroid, users can install without sideloading and receive update notifications.
The full fdroiddata MR can follow at any time without disrupting IzzyOnDroid users (different
signing key, different "store").

## Major blockers for full fdroiddata

### 1. `android/` is not committed to the repo (biggest blocker)

BirdEcho uses Expo Managed Workflow — `android/` is gitignored and generated by `expo prebuild`.
F-Droid's build server must run `expo prebuild` before Gradle, which is non-standard and will
likely get reviewer pushback.

**Recommended fix:** commit the generated `android/` directory on a dedicated `fdroid` branch.
Point the recipe's `commit:` at that branch's HEAD. Keep using EAS for your own release builds;
maintain the `android/` snapshot separately when cutting F-Droid releases.

**Alternative:** leave `android/` gitignored and rely on the `sudo: / init:` prebuild steps in
the YAML recipe. This is technically possible but may fail F-Droid's reproducibility checks and
will require manual testing with `fdroid build --on-server`.

### 2. Reproducible builds

Expo + Hermes is not reproducible today (timestamps in prebuild output, non-deterministic Hermes
bytecode, Metro bundle hashes). The `Binaries:` + `AllowedAPKSigningKeys` path will not work
without significant effort.

This means F-Droid will sign the APK with their key — users who installed from GitHub Releases
**cannot receive F-Droid updates without reinstalling**. This is acceptable for an initial
submission.

### 3. Sentry anti-feature

`@sentry/react-native`'s Java/Kotlin layer compiles into the APK regardless of whether the DSN
env var is set. F-Droid's scanner will detect it and require the `Tracking` anti-feature tag.

Options:

- **Keep it** (current default): declare `Tracking`. App is hidden by default in the F-Droid
  client unless the user enables anti-feature display. ~98 apps carry this tag.
- **Strip it for F-Droid builds**: uncomment the `sed` line in `init:` in the YAML recipe.
  Produces a Sentry-free binary; remove the `AntiFeatures` entry.

### 4. Google Maps API key (v0.5.0+)

`react-native-maps` is compiled in from v0.5.0. F-Droid builds ship without
`EXPO_PUBLIC_GOOGLE_MAPS_API_KEY`, so the Map tab renders a "Map not available in this build"
fallback rather than mounting the native Google map (which crashes without a key — issue #25).
All other features are unaffected. F-Droid reviewers may ask about it; point them to the README note.

## Checklist before opening the fdroiddata MR

The YAML (`dev.arunrajiah.birdecho.yml`) has been updated with real commit SHAs for all tagged
releases through v0.5.0. Before submitting, still need:

- [ ] Replace the Node.js tarball URL and SHA-256 placeholder with the current Node 24 LTS
      patch version. Check https://nodejs.org/dist/latest-v24.x/SHASUMS256.txt.
- [ ] Decide whether to commit `android/` to an `fdroid` branch or rely on the prebuild steps.
      If committing, update each build entry's `commit:` to point at the fdroid-branch commits
      rather than the release tag SHAs.
- [ ] Decide on Sentry: keep `Tracking` or uncomment the strip line in `init:`.
- [ ] Verify the `react-native-maps/android/libs` rm entry — check whether that directory
      actually exists after `expo prebuild` at v0.5.0. Remove the `rm:` entry if not needed.
- [ ] Run locally: `fdroid lint metadata/dev.arunrajiah.birdecho.yml`
- [ ] Run locally: `fdroid build --on-server dev.arunrajiah.birdecho`
- [ ] Uncomment `AllowedAPKSigningKeys` + `Binaries:` if reproducible builds are ever achieved.

## F-Droid process overview

1. Fork https://gitlab.com/fdroid/fdroiddata
2. Create `metadata/dev.arunrajiah.birdecho.yml` from the draft in this directory
3. Run `fdroid lint metadata/dev.arunrajiah.birdecho.yml` locally
4. Run `fdroid build --on-server dev.arunrajiah.birdecho` locally
5. Open a Merge Request; F-Droid bots and a human reviewer will check it
6. Review typically takes 2–8 weeks
